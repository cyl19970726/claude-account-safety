# 04 浏览器 Profile、WebRTC 与一致性

## 目标

让登录 Claude 的浏览器环境**独立、干净、与真实位置一致**。不是把指纹改成另一个国家，而是避免日常浏览器里的插件、Cookie、WebRTC、DNS 把真实环境泄漏出来。

## 推荐做法

1. 为一个 Claude 账号使用独立浏览器 profile，或独立指纹浏览器环境。
2. 不要在同一个 profile 里登录个人邮箱、社交账号、公司 SSO 和大量无关站点。
3. 不要导入日常浏览器的 Cookie/密码/历史。
4. 语言/时区/地区设置与**真实所在地**一致；不要为了“看起来像美国”而改。
5. WebRTC 设为 Disabled 或 Replace，避免暴露本地内网 IP 或真实公网 IP。
6. 检查 DNS 泄漏；浏览器 DNS 应走代理/加密解析。
7. 只装必要扩展；不要装来源不明的“指纹伪装/防封”扩展。

## 必测页面

- `https://browserleaks.com/webrtc`：看 ICE candidate 里有没有本地/真实 IP。
- `https://dnsleaktest.com/`：看解析器是否在代理出口附近。
- `https://ippure.com/claude.html`：第三方 Claude 环境检测；分数只作参考，不是官方认可。
- `https://claude.ai/cdn-cgi/trace`：看出口 IP/loc/colo。

测试时不要登录账号，不要输入任何凭据；这些页面只用于环境检查。

## WebRTC 怎么判断

- 只看到代理出口/公网 IP：可接受。
- 看到 `192.168.x.x`、`10.x.x.x`、`172.16–31.x.x`：本地内网泄漏；通常风险较低，但说明 WebRTC 没关干净。
- 看到真实公网 IP（与 trace 不一致）：高风险，必须处理。

浏览器版本不同，WebRTC 行为会变；每次大版本升级后重测。

## 指纹浏览器

AdsPower、Undetectable 等工具可以隔离 profile、代理、时区、语言、WebRTC。使用原则：

- 只用于你自己的账号，不共享给他人。
- 代理填本地 Clash mixed 端口，不要把住宅代理网关直接暴露给浏览器（国内直连常被干扰）。
- 不伪造身份资料、不绕过 KYC、不做批量注册。
- 工具本身也会收集数据；阅读其隐私政策，敏感账号不建议用来源不明的破解版。

## 多账号

- Anthropic 官方支持一个人使用多个账号，推荐用独立配置目录（`CLAUDE_CONFIG_DIR`）隔离。
- 不要把账号借给他人、不要拼车、不要共享登录凭据。
- 多账号不能用来绕过额度或封禁；被限制后换号继续使用属于规避。

## 浏览器层验收

| 项 | 通过标准 | 证据 |
|---|---|---|
| 出口一致 | trace 的 `ip` 与代理出口一致 | 截图/记录 |
| WebRTC | 无真实公网 IP | browserleaks 截图 |
| DNS | 解析器不在本地 ISP | dnsleaktest 截图 |
| 时区/locale | 与真实所在地一致 | 浏览器 `Intl` 检查 |
| Profile 隔离 | 无个人 Cookie/密码导入 | 人工确认 |
| 扩展 | 只装必要扩展 | 人工确认 |
