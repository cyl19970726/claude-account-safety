# 10 设计说明与证据边界

## 这份 Skill 怎么来的

它来自三类材料的交叉验证：

1. Anthropic 官方政策、支持地区、Claude Code 文档。
2. 公开的 Claude Code 客户端研究与社区实测。
3. 本机环境配置经验：固定出口、DNS/WebRTC 防泄漏、时区/locale 一致性、账号卫生。

为了避免把个人机器配置、商家订阅和凭据带进公开仓库，公开版做了这些删减：

- 不包含任何住宅 IP 商家列表或购买链接。
- 不包含任何个人订阅 URL、节点 UUID、账号、密码。
- 不包含个人私有仓库路径或机器特定配置。
- 不把“改时区/指纹浏览器”写成绕过地区限制的操作步骤。

## 可以复用的部分

- 固定出口、单一客户端、TUN + rule、DNS 防泄漏、QUIC 禁用、WebRTC 检查。
- 新机器验收顺序：系统 → 网络 → 浏览器 → Claude Code → 账号。
- `claude.ai/cdn-cgi/trace`、IPPure、browserleaks、dnsleaktest 这些检查入口。
- 账号卫生：固定设备/环境、不共享、支付合规、被封后走申诉。

## 不能当成事实的部分

- 社区经验（E4）和商家宣称（E5）不能当成官方规则。
- “住宅 IP”“纯净 IP”“防封节点”不是官方认可，也不能保证不封。
- “改时区/语言/指纹”只有在**真实所在地就是那里**时才成立；否则是伪装，违反政策边界。
- “新环境养新号”“被封过的号不要在新环境登录”不是官方规则，也不应被写成规避封禁的流程。

## 客户端证据边界

公开研究和本地复核能确认：

- 客户端会读取/上报时区、locale、代理端点、gateway 分类等信号。
- 旧版 Claude Code 2.1.91–2.1.196 曾被发现使用日期分隔符/Unicode 撇号做地区标记；约 2.1.197 移除；2.1.312 样本未再找到。
- 没有公开证据能还原“账号综合权重公式”或“某个字段单独决定封号”。
- 服务端风控规则不可见。

因此，本 Skill 只做：

- 降低可观测的环境异常。
- 让配置可复现、可验收、可回滚。
- 帮用户在误封时整理申诉材料。

不做：

- 保证不封。
- 伪造身份/位置。
- 绕过 KYC/支付/地区限制。
- 轮换设备 ID 或清理指纹来规避关联。

## 为什么不放商家采购页

公开仓库里放“买美国住宅 IP”的商家列表，容易被理解成规避地区限制的采购指南，也会带来：

- 商家/affiliate 利益冲突。
- 价格、库存、ASIN 类型快速腐坏。
- 读者把“住宅”误当成“官方认可”或“免封”。

所以公开版只保留 `11-egress-options.md` 的评估维度：ASN 类型、共享/独享、静态/轮换、日志、KYC、退款、ToS。具体供应商由使用者自己选、自己买、自己核验。
