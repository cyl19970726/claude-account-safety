# 08 故障排查

## 先停

遇到 403/429/529、登录循环、账号受限时：

1. 停止重复请求，不要连续重试。
2. 不要换号、借号、切中转继续。
3. 记录时间、request ID、错误原文、最近的部署/网络变更。
4. 先判断是网络、客户端、账号，还是服务端。

## 403

常见原因：

- Cloudflare 挑战/反爬：裸 `curl claude.ai` 经常 403，不代表账号有问题。
- 代理出口被拦截。
- 请求头/客户端异常。
- 地区限制。

处理：

- 用真实浏览器打开 `https://claude.ai`，看是否能进登录页。
- 对比 `https://claude.ai/cdn-cgi/trace` 与 `https://www.cloudflare.com/cdn-cgi/trace`。
- 不要用脚本绕过 Turnstile/hCaptcha。

## 429

常见原因：

- 速率/额度限制。
- 多设备/多账号共用同一出口。
- 长跑 agent 没有退避。

处理：

- 停止并等待，不要换号绕额度。
- 查 usage/limits。
- 给 agent 加指数退避、并发上限、停止条件。

## 529

通常是服务端过载/临时不可用。处理：

- 等待并重试（有上限）。
- 查官方 status。
- 不要把它当成封号。

## 登录循环 / OAuth 回不来

- 检查系统时间是否准确。
- 检查浏览器是否阻止第三方 Cookie/弹窗。
- 检查代理是否在 OAuth 回调时切换了出口。
- 用同一浏览器 profile 完成登录；不要在登录中途换节点。
- 仍失败时，保存错误页截图（脱敏）并走官方支持。

## DNS 泄漏

- 系统 DNS 仍指向本地 ISP。
- 浏览器开启了“安全 DNS”绕过代理。
- TUN 没有接管 DNS。
- 代理规则把 DoH 域名走了 DIRECT。

处理：

- 先看 `scutil --dns` / `resolvectl` / `Get-DnsClientServerAddress`。
- 关闭浏览器自带 Secure DNS，或把它指到代理内的 DoH。
- 重跑 dnsleaktest。

## WebRTC 泄漏

- 浏览器 WebRTC 没关。
- 扩展/会议软件绕过代理。
- 多网卡（Wi-Fi + 有线 + VPN）同时在线。

处理：

- 浏览器设置/扩展禁用 WebRTC。
- 只保留一个活动网卡。
- 重测 browserleaks。

## IPv6 泄漏

- 有 IPv6 默认路由，代理只接管 IPv4。
- 浏览器优先走 IPv6。

处理：

- 关闭目标网卡 IPv6，或让代理明确接管 IPv6。
- 重测 trace 的 `ip` 是否仍是代理出口。

## 双代理客户端打架

症状：时通时断、TUN 路由乱、DNS 随机。

处理：

- 只保留一个客户端。
- 退出另一个，确认没有残留进程。
- 重开 TUN/系统代理，按顺序验证。

## Claude Code 更新后异常

- 记录旧版本和新版本。
- 检查是否混用了 npm/原生安装。
- 检查 `ANTHROPIC_BASE_URL` 是否被第三方工具写入。
- 回滚到官方上一版，不要装“防封魔改版”。

## 账号受限

- 不要换号继续。
- 走 Restricted Account 申诉。
- 保存证据，停止触发警告的工作流。
- 如果是误判，提供事实，不提供虚假身份。
